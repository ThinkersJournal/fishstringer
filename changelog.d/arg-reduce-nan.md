kind: Vulkan argmax/argmin kernels follow the NaN rule (a NaN wins, first NaN's index)
---
All eight `arg_reduce_{last,any}_dim_{f32,f16,bf16,f64}` Slang kernels ignored NaN (every comparison against NaN is false), so `[1,NaN,0,5]` gave argmax 3 / argmin 2 where the torch convention, already the CPU rule, gives 1 / 1. They now use a NaN-aware comparator (`take_new`): a NaN displaces any non-NaN best, nothing displaces a NaN best except an earlier-index NaN (so both ops return the FIRST NaN), and the shared-memory tree merge treats two NaNs as equal so the lower index wins; without NaN, ties keep the first index and -0.0 == +0.0 as before, and an all-NaN row gives 0. Compiled with slangc 2026.8 via `kernels/compile.sh`, all 8 outputs pass `spirv-val --target-env vulkan1.1`. Device vectors (fuel's `vulkan_arg_nan_vectors_live`): see the follow-up commit. Unchanged contract limit: the bf16 last-dim kernel needs an even `n_cols` (lane pair).
