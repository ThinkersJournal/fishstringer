kind: Vulkan argmax/argmin kernels follow the NaN rule (a NaN wins, first NaN's index)
---
All eight `arg_reduce_{last,any}_dim_{f32,f16,bf16,f64}` Slang kernels ignored NaN (every comparison against NaN is false), so `[1,NaN,0,5]` gave argmax 3 / argmin 2 where the torch convention, already the CPU rule, gives 1 / 1. They now use a NaN-aware comparator (`take_new`): a NaN displaces any non-NaN best, nothing displaces a NaN best except an earlier-index NaN (so both ops return the FIRST NaN), and the shared-memory tree merge treats two NaNs as equal so the lower index wins; without NaN, ties keep the first index and -0.0 == +0.0 as before, and an all-NaN row gives 0. Compiled with slangc 2026.8 via `kernels/compile.sh`, all 8 outputs pass `spirv-val --target-env vulkan1.1`. Rebuild: `fishstringer-kernels-source/kernels/compile.sh --out-dir DIR arg_reduce_*.slang` (slangc 2026.8, Python 3.15.2, Vulkan SDK 1.4.350.0 `spirv-val`). Device-run 2026-11-25 on the one adapter this lane has (AMD Radeon 610M, integrated; the RTX 4070 is not enumerated here) with the new `.spv` copied into a detached scratch worktree of fuel `680cf0f`: fuel's `vulkan_arg_nan_vectors_live` ran all 10 vectors x f32/f16/bf16/f64 x argmax/argmin; every non-skipped case got == want (e.g. `[1,NaN,0,5]` 1/1, `[1,5,NaN]` 2/2, `[NaN,1,5]` 0/0, `[3,NaN,NaN,1]` 1/1, 1024-row NaN@700 700/700; all-NaN, ties, +-0 and long-ties unchanged), 0 unlisted divergences. The test then FAILED by design: its 36 `KNOWN_DIVERGENT` pins (the old behaviour) now agree, so fuel must drop that list. bf16 cases on odd-length rows are skipped by the test (the kernel needs an even `n_cols`). Unchanged contract limit: the bf16 last-dim kernel needs an even `n_cols` (lane pair).
