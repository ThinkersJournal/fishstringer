kind: CI: install a pinned dxc and make the HLSL compile assertions fatal without it
---
The `slang-emit` job downloads Microsoft's DirectXShaderCompiler release v1.9.2609 (`linux_dxc_2026_09_28.x86_x64.tar.gz`), checks its sha256 (`96faadc7...a39a1`, the digest GitHub records, re-computed by hand from a download on 2026-11-26) and sets `FISHSTRINGER_REQUIRE_DXC=1`, so the dxc assertions of `lower_kernel_hlsl_collectives` fail instead of skipping when dxc is absent. Nothing of dxc is vendored or redistributed (a CI download), so no THIRD-PARTY-NOTICES entry is added. UNMEASURED: the Linux asset has not been run by this lane (only the 1.9.0.5347 Windows dxc ran the assertions locally); the first CI run of this change is its first measurement, a failing download makes CI red, which is intended. Red-first for the env var, run locally (dxc 1.9.0.5347 on the Windows box): with dxc NOT on PATH and `FISHSTRINGER_REQUIRE_DXC=1` the test FAILS with `FISHSTRINGER_REQUIRE_DXC is set but `dxc` could not be run` (red); the same run with the variable unset passes without running dxc (the vacuous skip this change removes); with dxc on PATH and the variable set all 7 tests pass (green). The first CI run is read and reported by the fishstringer lane. Shader model 6.6 is the minimum for the plain HLSL (`[WaveSize]`; vulkane measured an error at cs_6_0 and cs_6_5).
