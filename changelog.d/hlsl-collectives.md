kind: **BREAKING**: subgroup collectives lower on the new HLSL-only entry points (`Slang::lower_kernel_hlsl`, `lower_module_hlsl`)
---
Board 506. New public `Slang::lower_kernel_hlsl` and `Slang::lower_module_hlsl` lower a `Subgroup`-scope `Collective` to HLSL wave intrinsics: `Reduce` Sum/Prod/Max/Min/And/Or/Xor over `I32`/`U32`/`F32` (a float Max/Min declines by name: the HLSL NaN rule is unmeasured), `Shuffle` Idx/Up/Down/Xor (a lane with no source keeps its own value, as the oracle does), `Vote` All/Any (a `U32` 0/1) and `Broadcast`. The default `lower_kernel`/`lower_module` are unchanged and still decline every collective; `Scan`, `ReduceWith`/`ScanWith`, `CollectiveTuple`, `Vote` Ballot and block scope stay declined on both. Each collective is wrapped in `__target_switch { case hlsl: .. }` with no default, so `slangc` fails the text for SPIR-V, GLSL, Metal, WGSL and CUDA: the SPIR-V and GLSL declines are not lifted by the back door. Measured with slangc 2026.8: HLSL compiles, the other five targets fail, and an unguarded control compiles for all six. Test `lower_kernel_hlsl_collectives`: all 14 lowered forms compile for HLSL and are refused for SPIR-V and GLSL, a guard-removed mutant compiles for SPIR-V, the declines are named. A kernel with a collective must state ONE subgroup size (`LaunchShape::with_subgroup(n, n)`, a power of two from 4 to 128) or it declines by name: `n` is spelled as a literal in the shuffles and the entry carries `[WaveSize(n)]` (shader model 6.6; which driver accepts it is UNVERIFIED), because HLSL waves are 32 or 64 lanes and the oracle's `n` is the launch's. Shuffle edge rules follow the oracle: `Idx`/`Broadcast` read lane `operand mod n` (non-negative remainder), `Up`/`Down`/`Xor` keep the lane's own value when the source is outside `0..n`, an unsigned operand is compared in `uint` so a huge value cannot wrap into range. `I32` And/Or/Xor go through `uint` (dxc's `WaveActiveBit*` take only `uint`: found by vulkane with dxc 1.9.0.5347 on the first push, now asserted by running `dxc -T cs_6_6` on the `slangc -target hlsl` output of all 14 forms). The emitted text of `lower_kernel_hlsl` is Slang, not HLSL (dxc cannot read `__target_switch`): the pipeline is `slangc -target hlsl` then dxc. For a pure-Rust consumer that cannot run slangc (vulkane-hlsl-emit) a third public function, `Slang::lower_kernel_hlsl_plain`, returns the same lowering as plain HLSL with the intrinsics called directly and NO guard; the caller must prepend `#ifdef __spirv__ #error` and `#ifdef __SLANG__ #error` (vulkane's measurement: `__spirv__` is defined only by `dxc -spirv`, `__SLANG__` by slangc). Test: all 14 plain forms pass `dxc -T cs_6_6`, compile to SPIR-V under `dxc -spirv` without the guard (control) and fail there with it. NOT run on a device: the wave intrinsics are compiled, never executed, and WaveReadLaneAt with a per-lane (non-uniform) lane argument in Up/Down/Xor is UNVERIFIED against shader-model rules. The patent question (US8539204B2) stays open: docs/PATENT_SWEEP.md. Proposed 0.9.0: new public functions are additive, but a decline becomes a lowering on them, and a collective-using kernel's behaviour on the HLSL path is new (pm-assist rules).
