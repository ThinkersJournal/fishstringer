kind: `lower_kernel` declares the capabilities a kernel needs as interface tokens (row 17 E19, option b)
---
`Slang::lower_kernel` now appends the capabilities the generated source needs to `KernelInterface::requires`, spelled as the `<arith>` names of the `vulkan:` vocabulary and sorted: `i64` (any `int64_t`, which includes the params block of every kernel with a buffer), `f16` and `st16` (`half` kernels), `i16` and `st16` (bf16, whose buffers are `uint16_t`). `f64` is reserved: no `F64` kernel lowers yet. The atomics tokens (`a64`, `af32`, `af64`) wait for the vocabulary's next version. New public items: `VULKAN_ARITH_TOKENS` (the vocabulary's names, copied from `kiss-vulkan-vocab` at Vulkane commit `e55e7fbc2090acc54d9a8e02b80b01f59a5a656c`) and `unmet_requirements(interface, target_arith)`, the reference consumer-side gate that returns the tokens a target lacks. Nothing in unpopped checks `requires` against a target and a name is free-form, so the gate lives with the consumer (a launcher, or Vulkane, that holds the device's tokens); tests pin every emitted token to the vocabulary list (with a control that a misspelling is not in it) and check that the gate names the missing token. Additive. The prose fidelity notes stay.
The root `README.md` no longer says the repository is a placeholder, and `ROADMAP.md` rows 17, 18 and 20 drop their stale "blocked on" text (docs only).
Docs: the mbarrier statements (NVIDIA US11803380B2) are recorded as declined, possible exposure, board 434 C extended; no IR variant exists yet to refuse.
