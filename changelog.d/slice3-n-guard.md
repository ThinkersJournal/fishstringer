kind: `n` bounds guard on a plan kernel that carries a params block (E17 slice 3, Option A)
---
A plan kernel lowered with `CallerCaps::with_interface()` that reads a runtime `Param` now puts the element count first in its `ConstantBuffer`: `struct Params_ { uint n; float p0; ... }`, and its first statement after `uint i = tid.x;` is `if (i >= pb_.n) { return; }`, so a launch no longer has to be a multiple of 256. The interface's `params_block` states it: `n` (`u32`, offset 0), then `p<i>` at `4 + 4 * i`, size `4 + 4 * n_params`. Parameterless plans are unchanged: no block, no guard, exact dispatch, byte-identical text (asserted). Not part of any release yet (the block itself is row 1's, unreleased), so no consumer sees a layout change. Verified red-first (the block test failed before the change) and against two seeded mutants, each caught: the guard `>=` as `>`, and the `p<i>` offsets without the `+ 4`. slangc compiles the kernel; NOT device-run; the offsets are not yet cross-checked against slangc reflection for the plan path (the `lower_kernel` E2 test does that for the launched path). Multi-output and hetero out-dtype (the other two items in `docs/options-e17-slice3-abi.md`) are not in this commit.
