kind: take unpopped 0.61.0 (BREAKING): `UnaryOp::{Popc, Clz, Brev}` decline by name
---
The three crates now require unpopped, unpopped-vocab, unpopped-convert and unpopped-cpu-c `0.61.0` (replacing 0.60.23); a consumer on `^0.60` needs the same bump, so vulkane-slang-emit's `fishstringer-slang-emit` pin moves with it.

unpopped 0.61.0 added the integer bit operations `Popc`, `Clz` and `Brev` to `UnaryOp`. Both Slang paths decline them **by name**: the elementwise speller (`slang_unary`, before the dtype check, with a backstop arm in the float speller) and the kernel path (a `ScalarExpr::Unary` arm that names the op; before it the decline said only "this expression"). Nothing new is lowered: HLSL has `countbits`, `firstbithigh` and `reversebits`, but none is spelled or measured here, and `firstbithigh(0)` is -1 where the IR's `Clz(0)` is the operand width, so a lowering needs an edge rule first. No spec section was read for this change. `tests/bit_ops_decline_by_name.rs` checks all three ops at I32 and U32 against a control kernel that lowers (the pre-fix decline did not name the op and failed the test). 64-bit rows are not lowered by the kernel path at all. Patent wording for any later lowering: Popc/Brev outside as read; Clz "no patent found: not a clearance; no packed/vector clz". `cargo test --workspace` passes at this commit; no device run.
