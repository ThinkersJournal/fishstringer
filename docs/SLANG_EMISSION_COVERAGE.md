# Slang emission coverage: what `fishstringer-slang-emit` lowers, and the plan to emit everything Slang can express

Status: plan (docs only, no code). Task from the PM, relaying CireSnave's 2026-11-11 question: is the Slang emitter
comprehensive, given that our CUDA kernels (the most complete set, starting with the vendored FlashInfer paged decode,
`baracuda-kernels-sys/vendor/flashinfer/include/flashinfer/attention/decode.cuh` and
`kernels/attention/flashinfer_paged_decode_launcher.cu`) may parse into Unpopped's IR with no way to emit Slang?

## 1. Where it stands (measured at fishstringer main 159cd15, Unpopped origin/main fetched 2026-11-11)

**No, it is not comprehensive.** `Slang` implements `Backend::lower` for the scalar contiguous Elementwise path only
(`StructuredBuffer<T>` inputs, one `RWStructuredBuffer<T>` output, `[numthreads(256,1,1)]`, `output[i] = body`;
`fishstringer-slang-emit/src/lib.rs`). It does **not** override `Backend::lower_kernel`, so the default applies and every
kernel-layer `KernelFn` gets `LowerError::UnsupportedKernel` (pinned by
`tests/lower_kernel_default_is_the_typed_decline.rs`). Even on the Elementwise path it declines f16/bf16, params,
multi-output, hetero out-dtype and the polyfilled ops (`Erf` family, `Cbrt`, `Asinh`.., `Copysign`, `Nextafter`).
Only `unpopped-cpu-c` overrides `lower_kernel` (serial C, a correctness reference). The IR statement set it must cover
is `unpopped::kernel::Stmt` (Let, Load, Assign, Store, MaskedLoad/Store, If, For, While, Break/Continue/Return, Barrier,
AtomicRmw/Cas, Fence, Collective(Tuple), Mma, CopyAsync, AsyncCommit/Wait, Call(Tuple), ExternCall) over `Place`
(Logical, Alloc, ClusterPeer, Peer) and `ExecId`.

**Rule for every row below** (the IR-superset standard): a construct Slang can express is emitted and tested; one it
cannot is a **recorded gap in the target**, declined with `LowerError::UnsupportedKernel` whose `detail` starts
`slang: <construct>: <reason>`, never a silent refusal or an approximation. Each decline gets its own test that asserts
the variant and the reason prefix. Spellings marked *probe* are my reading of Slang's documented surface and must be
confirmed with `slangc` (pinned 2026.8) **and** run on a device (AMD 610M, RTX 4070, Lavapipe) before the row closes;
the row's test is the proof, not this table.

## 3. One row per construct family

Sizes: S = under a day, M = a few days, L = a week or more. "Gap" = Slang cannot express it; the decline is the deliverable.

| Row | Family | How it lowers (or why it cannot) | Owner | Size | Test that shows it |
|---|---|---|---|---|---|
| E4 | `Let`/`Assign`/`If`/`For`/`While`/`Break`/`Continue`/`Return`, masked load/store | direct C-style statements. `MaskedLoad` = `T v = fill; if (mask) v = b[i];` (memory untouched when false). `For` zero step traps in the oracle; a GPU cannot trap, so emit only when the step is a nonzero constant, else decline `slang: For: step not a nonzero constant`. Loop `[unroll]`/`[loop]` hints: the IR has no hint field, so none are emitted (non-semantic); ask Unpopped for an optional hint if FlashInfer's `#pragma unroll` performance matters. | fishstringer | M | per-statement kernels vs oracle; decline test for a dynamic step |
| E5 | `groupshared` memory, static extent (`Place::Alloc`, `MemorySpace::Shared`; `Private` -> function-local array; `Constant` -> `cbuffer`/`static const`) | `groupshared T a[N];` declared at module scope (entry-point-local `groupshared` is not allowed), one declaration per `AllocDecl`. | fishstringer | S | shared-tile transpose kernel vs oracle |
| E6 | `groupshared` **dynamic extent** (`Extent::Param`; CUDA `extern __shared__`) | Slang/HLSL has **no dynamic shared memory**. | E7 | Barriers: `Barrier{Block}`, `Barrier{Subgroup}`, `Fence` | Block: `GroupMemoryBarrierWithGroupSync()`. The 17 `n_sg` kernels (fishstringer#14) are the existing live evidence for size-8. | fishstringer | L | each collective vs oracle on AMD (wave32/64), NVIDIA (32), Lavapipe (8) |
| E9 | Block-scope `Collective` (`Reduce`/`Scan`/`ReduceWith`/`ScanWith`/`CollectiveTuple` at `Block`) | no single Slang intrinsic: derived lowering = per-subgroup `Wave*` then a `groupshared` combine and two barriers (what CpuC does as "a block-level construct between two thread loops"). `ReduceWith`/`ScanWith`/tuple forms call the module `combine` function through shared memory in lane order, to match the oracle's left-to-right fold. Float order differs from a device-native tree: compare within the band. | fishstringer | L | argmax `(value,index)` and Welford tuple vs oracle |
| E10 | Atomics: `AtomicRmw{Add,Max,Min,And,Or,Xor,Exchange}`, `AtomicCas` | `InterlockedAdd/Max/Min/And/Or/Xor/Exchange/CompareExchange` on a `RWStructuredBuffer`/`groupshared` element; `old` = the out parameter. **Capability-conditional:** `F32`/`F64` Add/Exchange need the float-atomics device feature, 64-bit integer atomics need the 64-bit atomics feature: decline `slang: AtomicRmw f32 Add: target lacks shaderBufferFloat32AtomicAdd` using the KISS capability vocabulary (needs a field; see E19). `order`/`scope` are not selectable in classic HLSL `Interlocked*`: the result is relaxed-or-stronger device-coherent, which satisfies every order the IR names; Slang's `Atomic<T>` with `MemoryOrder` *probe* can restore the distinction. **Gap:** `Cluster` scope; atomics on `Peer`/`ClusterPeer` places. | fishstringer | M | histogram + CAS lock kernel vs oracle; float-atomic decline test on a device without the feature |

## 4. Order and dependencies

E1 (decided with Unpopped) -> E2 -> E3 first; then E4 -> E5 -> E7 (a block-reduce kernel needs all three) -> E12; E8, E10,
E11, E14, E18 are independent of each other once E3 exists; E9 needs E5+E7+E8; E13 needs E2+E4+E12 and 64-bit from E11/E19;
E15 and E16 last. E17 can run any time. FlashInfer paged decode is expected to need E2, E4, E5, E7, E8, E9, E11 (f16/bf16),
E12, E13 and probably E10; E15 only for the tensor-core variants.

## 5. Unpopped's answers (message from the unpopped lane, 2026-11-11; Unpopped origin/main 0948bcd7)

1. **`KernelInterface` on `GeneratedKernel`:** an additive field is non-breaking (`GeneratedKernel` is `#[non_exhaustive]`
   with private fields, `GeneratedKernel::new(name, source)`; CpuC spells its calling convention only in the C text).
   Unpopped's sketch: entry, workgroup from `LaunchShape.block`, grid, subgroup, bindings (param index, name, element,
   role, rank), scalar params (local, type), dynamic Shared allocs (alloc, param local), set by a builder. **The API shape
   was the PM's to rule: **ruled 2026-11-11** (a) `KernelInterface` additive, built by Unpopped as the next 0.44.x PR after #332/#333, derived core-side by `KernelInterface::of(&KernelFn)` (launch, params, dynamic_shared) plus emitter-set binding slots; row 17 may design against the field list Unpopped posts. Fishstringer asked for three optional emitter-set fields (`compiler_args`, `requires`, `params_block`); **Unpopped built them** on a branch (not yet a PR as of 2026-11-11), with `bindings`, `entry_symbol`, `spec_constants`, `fidelity_notes`, `launch_bounds`, `max_regs`, `cooperative`, `buffer_guarantees`, via `GeneratedKernel::with_interface`/`interface()`; `GridDim` is reported as a `params_block` field; (b) the `For` unroll hint is breaking, planned 0.46.0 (S4 stays 0.45.0), and emitters treat it as optional.
2. **`GridDim`:** yes, grid and block are numbers in `KernelFn.launch`, visible to `lower_kernel`. **`Extent::Param`: no**,
   it is a scalar kernel parameter fixed per launch, not known at lower time. For static `groupshared` the choice (refuse,
   specialization constant, or a variant per size) is the emitter's; a refusal is a gap row on our side (E6 stands as written,
   with the "bound at pipeline build" wording read as "per launch, so a specialization constant or per-size variant").
3. **Unroll hint on `Stmt::For`:** none exists (the schedule language is ROADMAP P9, deferred). A non-semantic field on
   `For` is the clean shape but `Stmt` is exhaustive, so it is a **breaking** change (size S-M), going to the PM with Q1.
   E4 emits no hints until then.
4. **CUDA lifting:** **no CUDA to `KernelFn` lifter exists.** `convert.rs` lifts only elementwise/reduction/scan idioms and
   refuses `__shared__`, `__shfl`, `asm`, `cp.async` and barriers. Unpopped's `paged_attention`
   (`crates/unpopped/tests/support/attention.rs`, U10 A4) is hand-written: one thread per sequence, f32, no shared memory
   or shuffles, and **not a port of `decode.cuh`**. A body lifter (XL) is being scheduled by Unpopped after its #332 and S4.
   Consequence for E13: the paged-gather row can be tested on that hand-written kernel, but emitting the FlashInfer decode
   itself waits on the lifter, or on a hand-written IR port of `decode.cuh` (not planned by anyone yet).
